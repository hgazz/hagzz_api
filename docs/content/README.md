## ما تغير في API

- الصفحة الرئيسية تعرض البنرات المفعلة للدولة المطلوبة فقط، بدل عرض بنرات مصر وقطر وغير المفعلة معًا. ينطبق على الضيف والمستخدم المسجل.
- صور Gallery وCoach تستخدم نفس StorageUrl الخاص بباقي صور التطبيق، بما يدعم التخزين الحالي والروابط الكاملة ويستبدل روابط التخزين القديم المفقودة بالصورة البديلة الموجودة. لا يستعيد ذلك الصور المحذوفة نفسها.
- أمر تثبيت اختياري للصور الثلاث لكل من مصر وقطر، يعاين الروابط دون كتابة افتراضيًا. مع `--apply` يضيف ستة سجلات مرة واحدة داخل transaction. إعادة تشغيله لا تكررها ولا تعيد تفعيل بنر أوقفه الأدمن، ولا تحذف الحملات القديمة.

## النشر والتفعيل

هذه تغييرات API وملفات ثابتة، لا تحتاج تحديث Google Play لعرض البنرات والصور بعد وصولها من API. يلزم نشر نسخة API أولًا. من مجلد البنية التحتية على السيرفر، بعد جلب master لمستودع hagzz_api وبناء وتشغيل خدمة api، نفذ الأوامر منفصلة:

```bash
docker compose exec -T -w /var/www/html api php artisan hagzz:brand-banners
```

تحقق أن الروابط تعرض دومين API العام عبر HTTPS، لا localhost أو نطاقًا قديمًا، وأن كل رابط صورة يرجع 200 وContent-Type مناسبًا من خارج السيرفر. APP_URL هو مصدر هذه الروابط؛ صححه وأعد إنشاء config cache عند الحاجة قبل التفعيل.

```bash
docker compose exec -T -w /var/www/html api php artisan hagzz:brand-banners --apply
```

تحتفظ استجابة الضيف بالنتائج مؤقتًا لمدة دقيقة؛ انتظر انتهاء الكاش ثم أعد فتح التطبيق. لا تمسح الكاش العام دون داعٍ. يمكن إيقاف البنرات القديمة المفقودة فرديًا من الأدمن بعد مراجعتها؛ لا يفعل الأمر ذلك تلقائيًا. اختبر الصفحة الرئيسية في حساب مصري وآخر قطري، وتحقق من الصور في النسخة المنشورة من التطبيق.

## بيانات الأكاديميات الحقيقية: بانتظار المصدر

الوصول من بيئة التطوير إلى app.notion.com وwww.notion.so مرفوض من بروكسي الاتصال (`CONNECT 403`) قبل تحميل الصفحة. لم تُقرأ محتويات المصدر، ولا توجد ادعاءات باستيراد أكاديميات أو تدريبات منه. يلزم تصدير CSV أو HTML مع الصور وإرفاقه لإتمام الجرد والمراجعة والاستيراد. `approved-catalog-template.csv` قالب خالٍ من الصفوف يوضح البيانات المطلوبة، وليس أداة استيراد منفذة.

لكل تدريب يلزم: اسم الأكاديمية والفرع، شعار وصور معتمدة، رابط المصدر، الرياضة، السعر والعملة (EGP أو QAR) ووحدة السعر/عدد الحصص، الأعمار والسعة، أيام ومواعيد التدريب والمنطقة الزمنية وتواريخ السريان، وحق نشر التدريب وإتاحة الحجز. تستخرج البيانات من المصدر المعتمد؛ لا تُخمن أسعار أو فروع أو مواعيد، ولا تُنشأ بيانات دخول للأكاديميات دون أساس.

## شرط قبل تفعيل حجوزات قطر المدفوعة

مسار `buildPaymentSdk` في تطبيق العملاء يمرر `CheckoutOptions(price, "EGP")` وعنوان EGY إلى Geidea، مع عملة EGP ثابتة أيضًا في analytics. تجهيز صور السلايدر لا يعالج ذلك. يلزم مراجعة دعم الدفع الفعلي لقطر، وتمرير العملة والبلد الصحيحين والتحقق من API والتحصيل، ثم إصدار نسخة متجر عند تعديل كود العميل. لم يجر تفعيل أو تحصيل أي حجز قطري في هذا التغيير.
